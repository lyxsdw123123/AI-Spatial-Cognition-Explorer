# AI 空间认知探索系统

本项目对应论文 `Thinking on Maps: How Foundation Model Agents Explore, Remember, and Reason Map Environments`，论文文件位于根目录 `thinking on map .pdf`。

项目核心目标是把基础模型 Agent 放入一个“有限视野、逐步探索、持续记忆、最后答题”的地图环境中，观察它如何：

- 探索陌生空间
- 累积空间经验
- 构建可用于推理的内部表征
- 在标准化空间认知任务上表现出怎样的能力差异

与只做静态问答的地图评测不同，这个项目强调“经验驱动”的空间认知：Agent 不是一次性看到整张图，而是在局部观察下逐步移动、记录、回忆、回答。

## 论文对应的研究框架

根据论文，系统把地图空间认知拆成三个相互耦合的环节：

1. 探索（Explore）
   - Agent 在部分可观测地图中逐步移动，只能看到当前位置附近的局部环境。
   - 论文设置采用符号化网格地图，核心元素包括道路、路口和 POI。
2. 记忆（Remember）
   - Agent 将探索过程中积累的局部观察编码为不同形式的记忆。
   - 重点比较不同记忆结构对后续空间推理的影响。
3. 推理（Reason）
   - 在探索结束后，用统一题型评估 Agent 的方向、距离、邻近、密度和路径规划能力。
   - 再通过不同提示策略比较“同样记忆被如何使用”。

论文中的主要结论可以概括为：

- 探索策略会影响经验采样方式，但对最终总体准确率的影响相对有限。
- 记忆表示是最关键的设计轴，对距离估计和路径规划等任务影响尤其明显。
- 推理提示策略主要提升“已有空间经验的利用效率”，对弱模型帮助更明显。
- 单纯增大模型规模并不能稳定解决地图空间推理问题，结构化空间表征依然重要。

## 当前仓库实现了什么

当前代码库把论文中的核心思想落成了一个可运行的实验系统：

- `backend/`：FastAPI 后端，负责探索流程、记忆组织、评估接口与地图服务
- `frontend/`：Streamlit 前端，负责区域选择、地图展示、探索控制和结果查看
- `data/`：本地 Shapefile 数据，包含多个真实城市地块的 POI、道路、道路节点和格网
- `归档/脚本/`：批量实验、离线评估、统计分析等脚本

项目既支持交互式运行，也支持批量实验复现实验结果。

## 与论文的一致性和当前实现差异

为了方便使用，当前工程实现和论文概念大体一致，但在若干细节上存在“研究设计”和“工程落地”的差异：

- 论文使用 `20 x 20` 的符号化地图和固定局部观察窗口来做严格对照实验。
- 当前工程主要基于真实地理数据的本地 Shapefile 进行探索，并在后端生成适合评估的文本/图/地图记忆。
- 论文中重点讨论 `SDM / NSM / GM / MM` 四类记忆表示；当前前后端主流程显式支持 `raw`、`context`、`graph`、`map` 等模式，其中 `graph`、`map`、线性上下文最贴近论文的结构化记忆思想。
- 论文的五类任务是统一实验设计；当前代码中的静态题库生成器默认生成 `22` 题，覆盖五类空间认知任务。

如果你的目标是“论文复现”，建议把本仓库视为论文方法的工程化实验平台，而不是逐表逐图一比一复刻版。

## 核心能力

### 1. 地图探索

- 支持在本地真实区域数据上初始化探索边界和起点
- 支持切换不同区域数据
- 支持在地图上查看 POI、道路、探索轨迹和当前 Agent 位置
- 支持高德地图与 OSM 相关地图服务能力

当前前端可选的探索方式包括：

- `随机POI探索`
- `最近距离探索`
- `最短路径探索`

其中“最近距离探索”和论文中的 Nearest-POI 思想最接近；“最短路径探索”更偏向工程实验中的路径规划导向模式。

### 2. 记忆表示

当前系统围绕探索后的记忆组织提供多种输出形式：

- `raw`：原始探索过程/原始对话轨迹
- `context`：线性叙事式上下文记忆
- `graph`：节点-边关系为核心的图记忆
- `map`：偏全局结构的地图记忆

这使得同一段探索过程可以被转换成不同认知表征，再用于评估和问答。

### 3. 空间认知评估

论文中的五类核心任务在当前项目中都有对应能力：

- 方向判断 `DJ`
- 距离估计 `DS`
- 邻近判断 `PJ`
- POI 密度识别 `PDR`
- 路径规划 `PP`

当前代码中的题目生成器默认按以下分布生成 `22` 题：

- 方向判断：8 题
- 距离估计：4 题
- 邻近判断：4 题
- POI 密度识别：2 题
- 路径规划：4 题

### 4. 多模型比较

配置层和实验脚本支持多家模型服务，当前仓库主要围绕以下 Provider 组织：

- `qwen`
- `openai`
- `deepseek`
- `claude`
- `gemini`

## 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 配置 `.env`

项目会从根目录 `.env` 读取配置。常见字段包括：

- `AMAP_API_KEY`
- `DASHSCOPE_API_KEY`
- `DEEPSEEK_API_KEY`
- `OPENAI_API_KEY`
- `ZHIPU_API_KEY`
- `GOOGLE_API_KEY`
- `ANTHROPIC_API_KEY`
- `OPENROUTER_API_KEY`

如果你只使用本地数据探索，可先最小化配置；如果要接入在线地图或多家模型接口，需要补齐对应密钥。

### 3. 启动后端

```bash
python start_backend.py
```

默认后端地址：

- `http://127.0.0.1:8000`
- API 文档：`http://127.0.0.1:8000/docs`

说明：

- 启动脚本会优先尝试 `8000` 端口
- 如端口不可用，会自动尝试备用端口

### 4. 启动前端

```bash
python start_frontend.py
```

默认前端地址：

- `http://127.0.0.1:8501`

## 典型使用流程

1. 启动后端与前端
2. 在前端选择区域或加载本地 Shapefile
3. 设定起点、边界、模型与探索方式
4. 选择记忆模式并开始探索
5. 停止探索后生成上下文/图记忆/地图记忆
6. 调用评估功能，查看各题答案、推理过程与结果摘要

## 常用后端接口

以下接口是当前系统最常用的实验入口：

- `/exploration/init`：初始化探索
- `/exploration/start`：启动探索
- `/exploration/stop`：停止探索并生成报告
- `/exploration/status`：查看实时状态
- `/exploration/context`：获取当前上下文记忆
- `/exploration/raw_history`：获取原始探索历史
- `/memory/graph`：获取图记忆
- `/memory/map`：获取地图记忆
- `/evaluation/start`：启动评估
- `/evaluation/questions`：获取评估题目
- `/evaluation/result`：获取评估结果

## 批量实验脚本

用于批处理实验和离线分析的脚本当前主要位于 `归档/脚本/`，常见文件包括：

- `batch_exploration_experiment.py`
- `batch_exploration_nearest.py`
- `batch_exploration_shortest.py`
- `batch_exploration_qwen3.py`
- `evaluate_memory_reports.py`
- `evaluate_reports_3memory_with_raw.py`

这些脚本通常通过调用本地后端 API 完成批量探索、评估和结果汇总。

## 技术栈

- 前端：Streamlit、Folium、streamlit-folium
- 后端：FastAPI、Uvicorn、WebSocket
- 地理数据处理：GeoPandas、Shapely、NetworkX、GeoPy
- 模型接入：LangChain 及多 Provider 适配
- 数据处理：Pandas、NumPy

## 适合做什么

这个项目尤其适合以下用途：

- 研究基础模型在地图环境中的空间认知能力
- 对比不同记忆结构对空间推理的影响
- 评估不同提示策略对空间问答表现的提升
- 用真实城市小区域数据做交互式探索实验
- 作为论文复现、课程展示或 GeoAI 原型平台
